1. Database Implementation

CollectionKey fields
usersname, email, passwordHash, role, totalScore
teamsname, memberIds[], totalScore
conteststitle, startTime, endTime, status, problemIds[], participants[]
problemscontestId, type (mcq/coding/subjective), difficulty, points
submissionscontestId, problemId, submittedBy, status, score

Relationships:

  • Contest → Problems
  • Contest → Participants (users/teams)
  • User/Team → Submissions
  • Team → Users
  • Submission → Problem

3. Advanced NoSQL Features

3.1 Aggregation

AggregationPurpose
Contest leaderboardtotal score + rank per contestant
Problem statisticsaverage score per difficulty level
Submission statisticscount of submissions by status, per contest
Problems solved per userdistinct correct problems across contests
Team performancecombine team members' submissions into one score
Sample result: {name: "Team Lavender Trial", totalScore: 195.0}

3.2 Indexing

  • Unique index on users.email
  • Index on problems.contestId
  • Compound index on submissions (contestId, submittedBy)

Checked with explain() — queries use the index (IXSCAN), not a full collection scan.

3.3 Transactions

Used when one action needs to update more than one document at the same time:

  • New submission + attempt count on the problem
  • Submission score update + user/team total score
  • Team membership change + back-reference on the user

3.4 Redis

  • Live leaderboard (updated as scores change)
  • Login sessions (expire automatically)
  • Rate limiting on submissions

Tested: after 10 submissions in a minute, the 11th is blocked.
