1. Database implementation

CollectionKey fields
usersname, email, passwordHash, role, totalScore
teamsname, memberIds[], totalScore
conteststitle, startTime, endTime, status, problemIds[], participants[]
problemscontestId, type (mcq/coding/subjective), difficulty, points, attemptCount
submissionscontestId, problemId, submittedBy, status, score

Every collection is created with a $jsonSchema validator, so MongoDB rejects a bad document at insert time instead of leaving the check to the API. scripts/init_db.py creates the collections, validators and indexes, and can be re-run safely.

Relationships:

  • Contest → Problems
  • Contest → Participants (users or teams)
  • User/Team → Submissions
  • Team → Users
  • Submission → Problem

3.2 Indexing

IndexCollection and keys
uniq_emailusers (email), unique
by_contestproblems (contestId)
by_contest_and_submittersubmissions (contestId, submittedBy.refId), compound
by_problemsubmissions (problemId)
by_memberteams (memberIds), multikey
by_statuscontests (status)

The demo script runs explain() on two of these queries and prints the winning plan, which comes back as IXSCAN with the index name, so the query is not scanning the whole collection.

3.3 Transactions

Four operations in api/services.py run inside a session transaction, which is why Mongo runs as a replica set:

  • create_submission: insert the submission and increment problem.attemptCount
  • update_submission_status: set status and score, then add the score to the user or team total
  • add_team_member and remove_team_member: update the team and the user's back-reference together

3.4 Redis

  • Live leaderboard per contest in a sorted set (ZINCRBY on score change, ZREVRANGE to read the top N)
  • Login sessions as keys with a TTL of 3600s
  • Submission rate limiting: a counter per user in a 60s window, capped at 10

4. Intermediate demonstration

make demo runs scripts/demo.py against the seeded database and prints each step:

  1. Connection check on Mongo and Redis
  2. CRUD on a user: create, read, update, delete
  3. Indexed query on problems.contestId with the winning plan and index name
  4. Compound-indexed query on submissions by contest and submitter
  5. Transaction: submission inserted while attemptCount and the user total move with it
  6. All five aggregation pipelines with their results
  7. Redis leaderboard, session TTL and rate-limit counter

The demo cleans up what it creates, so it can be run repeatedly during the review.
